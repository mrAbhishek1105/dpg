## Acceptance targets

These are the project's own V1 targets, not industry standards. Measurements are from the
automated suite and a held-out synthetic corpus on a Windows 11 development machine.

| Metric | Target | Measured |
|---|---|---|
| Original values in outbound requests (covered cases) | 0 | 0 in proxy tests (JSON and streaming) |
| Known-format secret recall | ≥ 95 % | 98.3 % (held-out synthetic corpus, 705 secrets) |
| Detection precision | ≥ 90 % | 100 % on the same corpus (0 false positives, 0 masked look-alikes) |
| PostToolUse latency, 500-line file | < 100 ms | p95 29.5 ms end to end (process start included) |
| Coding task success drop | ≤ 10 points | Not measured (needs live agent runs) |
| Exact placeholder restoration | 100 % | 100 % in tests (incl. split at every byte of a stream) |
| Restorations outside the project | 0 | 0 (traversal, symlink, `.git` and device-path tests) |
| Fail-closed tests passing | 100 % | 100 % |

Synthetic corpora are generated by the project; real-world precision will be lower. Bare passwords
in prose with no key name are the known weak spot.
